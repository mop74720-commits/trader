# 消息官：信息来源与处理子系统

当前为 **intel-v3**：增加人工信源分级、独立五维规则评估、代码精选门槛，以及精选/全部动态/预测市场阅读视图。具体实现、参数、回放边界及与 AIHOT 的对应见 [AIHOT 参考与落地说明](intelligence-aihot.md)。下文的 v2 阅读优先级继续用于交易摘要排序；页面精选先经过 v3 门槛筛选。

实现目标是还原原系统公开可确认的职责关系：独立信息采集 → 整理后交给交易认知，而不是声称恢复未公开的消息官源码。原作者私有 TG/X 列表、采集算法、Digest Prompt 和内部数据合同未知。

## 当前数据流

```text
Fed / CoinDesk RSS ───────┐
Telegram 公共频道 ───────┤
Polymarket Gamma ────────┤   独立采集任务，无交易所权限
X Recent Search（关闭）─┤
本地 JSONL（关闭）───────┘
             ↓
清洗与标准化 → 来源/时间/内容版本 → 独立 SQLite
             ↓
相关性筛选 → 指令样式隔离 → 过期过滤
             ↓
转载去重 / 标题相似聚合 / 可能冲突标记
             ↓
来源权重 + 新鲜度 + 相关性 → 有界原文摘录摘要
             ↓
同一份摘要与证据 ID → Planner / Critic 决策快照
```

消息官可通过 `python -m trader.intelligence` 单独运行，也可随 `python run.py` 在独立线程运行。四个来源可并发采集；网络请求期间不持有交易锁或情报数据库锁。源失败保留最后成功内容，但不延长新闻有效期；网络失败不暂停交易。每源有独立轮询间隔、条件请求、失败计数、指数退避、下次调度时间，退避状态重启后保留。

## 来源配置与覆盖范围

默认配置：`config/intelligence.sources.json`。下列来源是本项目选择的公共研究样例，**不是已经确认的原系统私有列表**。

| 来源 | 实现与默认行为 | 覆盖限制 |
| --- | --- | --- |
| Federal Reserve | 官方 RSS，15 分钟检查，7 天有效期 | 只读 RSS 内的标题/摘要，非所有宏观数据 |
| CoinDesk | 公共 RSS，5 分钟检查，24 小时有效期 | 最近 feed 窗口，非全站全文 |
| Telegram | `t.me/s/binance_announcements` 公共预览，5 分钟检查 | 最近公开文本消息；不登录、不加入群、不读取私聊；无历史补采，媒体仅内容无文本则跳过 |
| Polymarket | Gamma API 的 Crypto 标签（本轮核实 tag 21），按 24h 成交量取前 30 个事件 | 事件下的开放子市场；排除已关闭/已过期市场，最多 500 条市场报价；不是全量市场，也非精确可成交概率 |
| X | Recent Search，Bearer Token，保存 `since_id` 与待续分页 | 默认关闭，在线调用未验证；需要显式启用并自行确认计费；搜索历史覆盖受提供商限制 |
| 自有 JSONL | 配置目录内的本地导出文件，单文件 ≤3 MB、≤500 条 | 不信任文件自带采集时间；以本次导入时间作为可用时间 |

X 分页未结束时保持原 `since_id`，直到完整读完当前分页才推进高水位，避免跳过旧页。每次只请求一页，分页待续间隔 30 秒；重试遵守退避。无可用凭据时显示明确错误，不伪造采集成功。更换 query 时请使用新的来源 ID，否则旧游标可能不适用于新查询。

RSS/Telegram 是最近窗口采集。停机跨过窗口后可能缺少消息，不声称支持完整补采；健康页面明确标注覆盖范围。`healthy` 只说明最近抓取和解析成功，不代表信息完整、真实或来源近期一定发布了新消息。

所有联网操作均为读取。没有社交发布、私信、登录、交易订单、模型调用或新增服务订阅。默认来源不需要 API key，新增 X 计费读取有独立启用开关。

## 配置字段

- `id`：稳定来源 ID，同一内容源修改身份应使用新 ID。
- `kind`：`rss` / `telegram` / `polymarket` / `x` / `jsonl`。
- `enabled`：是否启用。
- `group`：同一出版机构/来源家族；避免多个账号重复计入非重复来源组。
- `reliability`：人工配置的来源权重，范围 0–1，仅用于阅读排序，不是校准后的正确率。
- `interval_seconds`：30 秒至 1 天的轮询间隔。
- `ttl_seconds`：60 秒至 30 天的内容有效期。
- `keywords`：可选包含关键词过滤，与内置资产/主题识别同时满足才入选。
- `url` / `channel` / `tag_id` / `query` / `path`：对应适配器的输入。
- `token_env`：X 的 Token 环境变量名称，默认 `TRADER_X_BEARER_TOKEN`。不在配置写入 Token。

文件导入示例（仅格式示例，不含真实账号/凭据）：

```json
{"external_id":"article-001","title":"Bitcoin ETF update","text":"Attributed public report text.","url":"https://example.org/news/001","published_at":"2026-09-09T12:00:00Z"}
```

将文件置于配置文件目录内，配置 `kind: "jsonl"` 与相对 `path`。只导入已获授权可用于本实验的非敏感材料；本系统不做通用隐私识别。

## 标准证据与时间语义

每份证据保存规范化后的原文内容：`title`、`text`、`url`、来源 ID/来源组、内容哈希、`revision`、`published_at`、`updated_at`、`observed_at`、`first_observed_at`、资产/主题、隔离标记、处理器版本。**不保存整个页面 HTML 或请求响应头**；“原文”指源中抽取并清洗的文本，完整网页仍以来源链接为准。

- `published_at` 是来源声称的发布时间，缺失时标为 `observed_only`，不猜日期。
- `observed_at` 是本系统首次采集该内容版本的墙钟时间，决定其最早可被模型读取的时间。
- 内容修改追加新版本，旧记录不覆盖；即使修改后恢复原文，也保留新的版本。
- 内容不变则不新增版本，另记观察时间。新闻仍以发布时间计算有效期；预测市场报价以最后实际观察时间计算有效期。
- `updated_at` 仅作为来源元数据，不能把新的内容“倒填”进旧回放。
- 发布时间比采集时间超前 5 分钟以上，隔离为 `future_publication_time`；超前但在容差内的报道也要等到发布时间后才进入摘要。
- 回放取截止时刻以前实际采集到的最近版本，来源健康也读取同一时刻以前的轮询日志。未来观察和未来修订均不可见。
- 摘要候选读取最近 2,000 个来源条目的当时版本；页面证据列表取最近 100 项，完整版本仍在数据库。

当前源启用列表是回放过滤条件，不保存配置历史；要做可复现实验，应冻结并保留配置文件版本。数据库保存来源权重和 TTL 于各证据版本中，后续配置更改不会回写已有证据。

## 去重、聚合与冲突

同来源相同外部 ID + 相同规范化内容不会重复建版本。跨源采用中英文标题词项相似度、资产/主题重合和 36 小时时间窗进行事件聚合。v2 额外要求标题状态及数字/单位词面一致；已识别资产完全不重合时不合并。预测合约身份使用来源 ID + 外部 ID。此保守约束可能增加漏合并，不能保证实体和单位语义解析正确。相同或高度相似正文视为转载，不增加“非重复来源组”估计；同一来源组也不会重复计数。

标题中否定标记不同的报道不会合并；正文背景中的否定不再直接翻转标题状态。高度相似标题出现肯定/否定差异时标记 `possible_conflict`。这只是可解释的启发式检测，不能可靠识别所有反讽、复杂否定、翻译、互相引用或协同传播。多源一致也不标为“已证实”，`verification` 始终为 `unverified` 或 `market_quote`。

预测市场不同合约不会因题目相似而合并。报价、流动性、24h 成交量和到期时间作为独立数值字段保存。Gamma 报价为采集时点的参考数据，不能直接解释为客观事件概率，也不保证盘口实际可成交。

## 摘要与事件通知

默认是**确定性的原文摘录摘要**，不调用模型、不做自动翻译或复杂事件推理。排序为来源权重 25%、新鲜度 25%、持仓/关注资产/宏观相关性 40%、标题中已报告安全事件的紧迫性 10%，每份摘要最多 12 组事件；同一出版方最多 6 组，预测市场最多 3 组，避免单一高吞吐来源占满上下文。

标题明确为奖励赛、推广收益活动等内容时，不进入摘要；上市、下架、提现暂停与安全事件优先保留。推广内容仍在证据库，摘要过滤使用当前处理器规则。

每组包括最多 600 字符摘录、5 条可追溯引用、资产/主题、冲突标志、发布时间与观察时间。摘要保留总证据数量，即使引用因长度限制被截断。

新入选内容/修订生成持久化通知，完全重复内容当日不重复通知。预测市场只有首次记录或相对上次已通知报价累计变动至少 5 个百分点时才通知；微小变动仍归档。比较基准通过既有通知对应的证据版本恢复，重启后仍有效；通知后重设基准。合约结果集合或题目/到期时间变化单独通知，成交量和流动性变化不单独触发通知。不保证通知是语义级“唯一事件”；近似标题改写可能产生多个通知。

通知目前用于本地观察与后续事件驱动接入，**不会自动唤醒付费模型或触发订单**。轮询认知时，Planner/ Critic 会读取时间截止一致的摘要。规则 Planner 继续仅使用价格因子，没有假装实现新闻交易策略。

## 外部文本边界

去除 HTML/script/style、清理不可见控制字符、限制文本长度，检测常见指令覆盖/风控绕过/凭据索取样式；命中后内容进入隔离区，不进模型摘要。链接只允许 HTTP(S)，去跟踪参数，拒绝带凭据字段的 URL。错误日志只保留异常类型或 HTTP 状态，不记录 Token、请求体和服务商异常正文。

上述规则是输入质量过滤，不能保证识别所有 Prompt Injection。模型系统指令同时说明外部内容是数据、须引用证据且无执行权限。当前模型调用不拥有采集服务文件权限，也不会执行新闻中的代码。未来接入 GenericAgent 通用工具时，需要另行评审其能力与权限边界。

## API

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/intelligence` | 来源状态、最新摘要、最近证据、通知 |
| GET | `/api/intelligence/digest?as_of=<ISO timestamp>` | 截止时刻摘要；不传参数则最新 |
| GET | `/api/intelligence/evidence/<id>` | 特定版本证据详情 |
| POST | `/api/intelligence/collect` | 唤醒调度检查；仍遵守每源轮询和退避 |

与现有本地 API 一样只监听 127.0.0.1，不改变既有访问控制策略。独立情报数据库避免交易账本结构迁移。新进程需要重启加载新代码和配置；使用独立 CLI 时不要与交易服务同时写同一个情报数据库。

## 与原架构的对应及未复现部分

已实现原架构职责：采集与交易分离、多源输入、先整理再交付、来源追溯、时效管理、独立健康状态和事件记录。具体算法、来源名单与阈值是本项目设计选择，不是原作者的实现。

尚未复现：GenericAgent Memory/Skill/Reflect、自主寻找信息源、登录态与私有 TG/X 采集、LLM 语义摘要/信源交叉核验、原系统未知的消息契约，以及新闻事件直接唤醒认知。X 在线端到端调用尚未验证。公共 TG 抓取依赖 HTML 结构，来源改版时会显式降级。

## v2 信息质量改进与评估边界

- `claim` 区分报道声称已发生、计划/预期、申请/受理、不确定、否定及未知；采用标题规则，始终保留 `unverified`。事件真实发生时间及影响期限未解析，显式为 null / unknown，不能用发布时间冒充。
- `summary_evidence_id` 指向摘录出处，首条引用始终是主证据；`evidence_ids` 保留全部聚合成员，页面最多展示五条引用。摘要指纹包含实际事件内容、全部证据、质量统计、排序上下文和处理器版本。
- `evidence_gaps` 与 `verification_request` 输出可交给下游核验的检查清单：一手来源未核对、单一来源组、冲突、时间/链接缺失、盘口缺失、结算规则未核对。请求标为 `not_performed`，不会伪装成已经执行补充检索。
- Planner / Critic 同一快照传入持仓及市场关注资产。最新页面使用当前账户上下文；API `?assets=BTC,SOL` 可指定关注资产。历史 API 默认通用视角，避免把今日持仓倒灌进历史；可显式附加 assets 进行假设情景研究。
- 分数提供四项加权贡献；权重是未校准的工程选择。每个出版方最多六项，所有预测报价合计最多三项。质量面板的资产证据缺口仅代表本次入选摘要，不能推断全网不存在证据。
- 状态页分别统计报道版本、报价版本及观察次数，避免将报价/流动性频繁变化误作新事件增长。状态累计计数不是历史时点计数；历史研究请使用 digest 接口。
- 摘要在读取数据库后释放锁再处理，减少聚合计算阻塞采集写入。全部扩展复用既有 JSON 字段和表；没有数据库迁移或新增依赖。

回放使用当时可见证据、当前处理器和当前启用源；要重现旧处理结果必须保存相应代码、配置与上下文。规则不能完整识别复杂否定、嵌套引语、多事件标题、共指及传播关系；没有实测新闻召回率，也未证明对交易收益有提升。下一阶段应在人工标注的相同输入上比较基线、规则处理、语义处理和主动核验，分别测量误合并、关键事件召回、证据忠实度、延迟和成本。

新增 `tests/test_intelligence_quality.py` 使用构造的对抗案例覆盖状态分离、背景否定、数字及资产差异、跨源合约身份、上下文排序、缺失证据、全局报价上限、主证据一致、完整摘要指纹、重启后的累计通知、结果集合变化和历史时间边界。这是回归测试，不是现实世界准确率评测。

### 本轮参考的一手规范（2026-09-09 核对）

- [W3C PROV Overview](https://www.w3.org/TR/prov-overview/)：来源追溯记录数据、处理活动和责任来源；本项目借鉴其追溯原则，不声称实现完整 PROV 标准。
- [CloudEvents specification](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md)：事件的 source + id 共同定义身份；本项目用于约束预测合约身份，不声称输出 CloudEvents 格式。
- [Polymarket Prices & Orderbook](https://docs.polymarket.com/concepts/prices-orderbook)：显示价可能为买卖中点，宽价差时可能为最近成交价，不能保证可成交。
- [Polymarket Resolution](https://docs.polymarket.com/concepts/resolution)：标题不是完整结算规则。当前 Gamma 数据未核对完整规则与盘口，摘要明确列为证据缺口。旧 CLOB 文档地址返回 404，已通过官方 llms.txt 找到当前说明。
