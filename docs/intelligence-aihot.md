# 借鉴 AIHOT 的信源与信息处理流程

本轮参考用户提供的《这个封装了我3年自媒体经验的AI热点网站，今天向所有人免费开放。》HTML，以及 [AIHOT 网站](https://aihot.news/)。文章中的来源数量、模型选择、迭代效果属于作者自述；私有 Prompt、五维定义、系数和分类阈值没有公开，本项目没有恢复这些内部实现。

网站访问核对：2026-09-09 / 10（北京时间），浏览器访问新旧域名返回 567，普通匿名只读 HTTP 请求取得 200，旧域名重定向至 aihot.news。参考其公开 HTML/CSS 中的精选/全部动态导航、分类筛选、日期时间线、主来源、推荐理由和相关报道折叠。没有复制其文章内容到交易信息池。

## 采用的做法

| 文章中的方法 | 本项目落地 | 目前边界 |
| --- | --- | --- |
| 先挑信源，T1 / T1.5 / T2 分层 | `tier` 与 `editorial_note` 写进来源配置；Fed 官方公告 T1、Binance 官方频道 T1.5、CoinDesk 媒体 T2 | 4 个启用来源；分级是人工判断，不是事实正确率 |
| 先判断相关性，再做评分 | 过滤无关、过期、指令样式、推广内容，再评估；机构名称本身不保证相关 | 使用规则；可能漏判，全部读取记录仍保留原文 |
| 分维度评估，代码重算总分 | `curation.assess` 提供五个有界规则维度；`curation.select` 使用配置计算分数和门槛 | 不是作者的五维定义，也不是 LLM 打分 |
| 类别与来源影响精选门槛 | 六类门槛 + T1/T1.5 门槛优惠；不确定标题扣分 | 初始工程参数，尚未通过人工标注集校准 |
| 同一事件只显示一条，优先官方 | 保留相似度、数字、状态与资产约束；同簇按 T1 → T1.5 → T2 → 未分级选主来源，完整相关报道可展开 | 当前为词项相似度，不是 embedding；同义改写、跨语言转载可能未合并 |
| 干净的精选和完整时间线 | 独立的精选、全部动态、预测市场视图；按北京时间分日期；搜索、类别、来源、24h/7d、分页与历史时间可组合 | “全部动态”是当前有界候选池中的相关报道，不等于完整历史或全网 |
| 让筛选可调、可评估 | 策略 JSON 与指纹；回归用例覆盖门槛变化与搜索/时间边界 | 没有自动反馈调参或未经授权的模型调用 |

## 当前处理链路

```text
人工审查来源与分级
  → 独立采集 / 规范化原文 / 保存观察与修订
  → 相关性、时效、推广与异常预筛
  → 保守聚合 / 一手来源优先 / 保留分歧
  → 五维规则评估
  → 代码加权 / 分类门槛 / 来源层级调整
  → 精选报道 | 全部相关报道 | 预测市场报价
  → 同时交付带证据的交易决策摘要
```

评估维度是：关注相关性、标题中的重要事件线索、信息具体程度、时效、来源配置权重。所谓“具体程度”只检查链接、数字和发布时间是否存在，不能证明数字正确或来源完整；“事件影响线索”只识别标题关键词，不能证明真实市场影响。

公式：`score = clamp(sum(dimension * weight) - uncertainty_penalty, 0, 100)`。
门槛：`threshold = category_threshold - tier_discount`。
只有报道且 `score >= threshold` 才进入精选；预测报价独立展示，不参与新闻精选。

配置位于 `config/intelligence.curation.json`，权重必须合计为 1，输入必须有限且在边界内；无效配置会明确启动失败。策略在进程启动时读取，编辑后需要重启加载。摘要包含版本与内容指纹，因此仅改数值也会改变策略标识。

原来的阅读优先级仍用于交易模型摘要的有限上下文排序；新精选分决定是否入选。页面精选按时间排序，不把高分等同于最热门；网站的社交热度指数没有被伪造为这里的市场热度。

## 数据与回放

- 来源等级写入新增证据 JSON；已有证据若没有此字段，则用当前配置补充，仅在读取副本中应用，不覆盖旧记录。新增证据已带等级时保持归档值。历史回放仍依赖当前启用源和处理器；精确复现需冻结代码、配置及关注上下文。
- 同一合并事件仅呈现主报道。主报道选择先比较来源层级，再比较来源权重和采集时间。聚合仍保留不同金额、不同状态、相反说法，不为了减少条数强行合并。
- 页面筛选在完整候选池上运行，再分页；不是在交易摘要的前 12 条中搜索。最多读取 2,000 个当时的来源条目，每页默认 30 条，上限 100。
- 加载更多固定 `as_of` 与关注上下文，避免更新插入造成漏项或重复；超过一页后保留浏览快照，点击“检查更新”重新开始。
- 新闻时间线使用主报道发布时间，缺失时使用首次收录时间；报价使用最后实际观察时间。旧新闻修订不会因新读取时间重新变成今日新闻。历史接口不读取未来采集版本。
- 右侧漏斗统计整个候选池，不随左侧时间窗口/类别/来源过滤变化。它统计条目和聚合事件，不代表全网新闻数量。
- 无数据库结构变更、无新增依赖。全部字段扩展复用已有 JSON payload。

## 页面 API

`GET /api/intelligence/feed`

参数：`mode=selected|timeline|quotes`、`window=24h|7d`、`category`、`source`、`q`、`limit`、`offset`、`as_of`、`assets`、`holdings`。后两项为显式排序假设，不修改账户持仓。分页时客户端保留响应的截止时间与上下文。

返回：分页事件、各视图匹配数、完整相关报道、五维评估、筛选结果与门槛、来源等级、处理漏斗、策略指纹、回放元数据。

## 验证与未实现项

构造用例覆盖：官方主报道优先、机构行政消息过滤、策略变更指纹、门槛与评估分离、漏斗计数守恒、超出前 12 条的搜索、固定时间分页、未精选内容可见、报价独立、旧闻不因修订重新入列、非主来源搜索。原有历史证据、报价累计通知、采集隔离和交易用例继续执行。

当前样本可能没有可合并的跨源报道，漏斗会如实显示合并 0 条。回归测试验证的是已知案例，不是现实世界准确率。尚未实现文章中的 LLM 预筛/评分/翻译、embedding 聚类、人工反馈学习或每日 08:00 固化日报；这些不能靠改文案宣称完成。

本轮验证：58 项 unittest 全部通过，JavaScript 语法检查通过；真实浏览器验证三个阅读视图、分类、空搜索/清除、固定时点加载 60 条且无重复、历史空结果与返回最新、来源详情、390px 手机布局。控制台无报错。2026-09-10 00:15 北京时间附近的本地样本：409 条输入，91 条相关性过滤、83 条过期、6 条推广，剩余 229 个事件（11 条新闻精选、8 条未精选报道、210 个报价）；重复合并为 0。单次 feed 本地请求约 0.37 秒，不是压力测试。新版运行于 8766 的独立预览数据库，8765 原模拟未中断。

另检查了 Ethereum 官方博客 RSS 作为潜在 T1 来源，但本环境返回 403，未将其加入默认启用列表。优先逐个核实来源和覆盖质量，而不是照搬文章中的 168 个来源规模。
